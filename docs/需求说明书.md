# 《Focusly番茄时钟\-专注学习打卡工具》需求说明书

## 1\. 项目概述

### 1\.1 项目背景

针对日常自习、科研学习、任务管控场景，开发一款轻量化、极简风格的在线专注打卡工具。解决学习专注力不足、任务杂乱、无学习数据记录、无法复盘学习时长的问题。本项目为前端实训专属项目，全程从零开发，结合AI Coding辅助完成编码、调试、优化。

### 1\.2 项目定位

轻量化单页Web应用（SPA），**采用Mock API模拟后端接口为核心数据源、LocalStorage为离线兜底**，无需真实后端服务器，即可实现标准前后端交互开发模式，集**番茄专注计时、学习任务管理、每日学习打卡、学习数据可视化统计**于一体的学生自用学习工具。

### 1\.3 开发目标

- *实现完整可用的自习专注工具，满足学生日常学习计时与任务管理需求；*

- 代码结构规范、分层清晰，适合迭代拓展；

- 全程AI辅助编程流程，实现“懂原理、会开发、善用AI、能调优”的实训目标；

- 界面简洁美观，支持电脑、移动端自适应适配。

### 1\.4 适用用户

研究生、大学生自习人群，核心使用场景：日常课程学习、备考专注学习等专注学习场景。

## 2\. 整体功能架构

项目整体分为四大核心模块，循序渐进迭代完成：

1. **番茄专注计时模块**：核心功能，支持自定义时长、计时控制、休息提醒；

2. **学习任务清单模块**：学习任务增删改查、状态管理，支撑专注学习目标落地；

3. **每日学习打卡模块**：记录每日学习行为，防止重复打卡；

4. **数据统计看板模块**：可视化展示周/月专注时长、学习数据复盘。

## 3\. 用户需求详细说明

### 3\.1 用户使用痛点

- 传统计时器功能单一，无法结合学习任务使用；

- 学习任务无统一管理，容易遗漏、拖延；

- 无每日学习记录，无法统计每周/每月学习投入；

- 第三方工具广告多、功能冗余、无法自定义适配学生需求。

### 3\.2 用户期望

- 界面极简无广告，操作简单，打开即用；

- 可自由设置学习、休息时长，灵活适配不同学习场景；

- 可以随时添加、修改、完成学习任务；

- 自动记录每日学习打卡与专注时长；

- 直观看到阶段性学习数据，辅助自我复盘；

- 刷新页面、关闭浏览器数据不丢失。

## 4\. 核心功能详细需求（PRD）

### 4\.1 番茄专注计时模块（核心功能）

#### 4\.1\.1 功能描述

提供可视化倒计时表盘，支持自定义学习时长、休息时长，实现计时启停、重置、自动提醒，模拟番茄工作法专注学习场景。

#### 4\.1\.2 具体需求

- **时长自定义**：用户可手动输入学习时长、休息时长，单位为分钟；输入非数字、负数、空值时自动容错提示，禁止非法数据录入。

- **计时基础控制**：包含开始、暂停、重置三个核心按钮；开始后倒计时递减，暂停后停止计时，重置后恢复初始设定时长。

- **计时结束提醒**：学习时长结束后，自动弹出文字提醒，提示进入休息模式；休息时长结束后，提示可继续专注学习。

- **定时器稳定性**：杜绝定时器叠加、后台持续计时、内存泄漏问题；页面切换、暂停时清空无效定时器。

- **可视化表盘**：展示时分秒实时倒计时，界面动态变化，视觉直观。

### 4\.2 学习任务清单模块

#### 4\.2\.1 功能描述

用户可自主添加当日/阶段性学习任务，对任务进行全流程管理，结合计时功能实现“任务\+专注”联动学习。

#### 4\.2\.2 具体需求

- **任务新增**：输入任务名称、简要描述，点击添加生成新任务，禁止空任务提交。

- **任务状态切换**：任务分为“未完成/已完成”两种状态，点击可切换状态，已完成任务文字置灰、添加划线样式区分。

- **任务修改**：支持编辑已添加的任务内容，实时更新展示。

- **任务删除**：支持单条任务删除、一键清空所有任务。

- **数据持久化**：所有任务数据本地存储，页面刷新、重启浏览器后数据不丢失。

### 4\.3 每日学习打卡模块

#### 4\.3\.1 功能描述

记录用户每日学习行为，生成每日打卡记录，作为后续数据统计的核心数据源。

#### 4\.3\.2 具体需求

- **当日打卡功能**：每日可提交一次学习打卡，记录打卡日期、当日专注总时长。

- **重复打卡拦截**：同一日期禁止重复打卡，点击打卡按钮自动判断当日是否已打卡，给出文字提示。

- **打卡状态展示**：日历/文本形式展示近期打卡记录，已打卡日期高亮标识。

- **打卡数据存储**：所有打卡历史数据永久本地保存，不自动清空。

### 4\.4 数据可视化统计看板模块

#### 4\.4\.1 功能描述

基于用户打卡、计时历史数据，自动聚合计算，通过图表可视化展示学习情况，支持学习复盘。

#### 4\.4\.2 具体需求

- **数据自动统计**：自动计算每日、每周、每月累计专注学习时长。

- **图表可视化展示**：通过柱状图/折线图展示近7天、近30天学习时长变化趋势。

- **数据自适应更新**：用户新增打卡、新增计时记录后，图表自动刷新数据，无需手动更新。

- **看板适配**：统计看板适配电脑、移动端屏幕，图表自动缩放。

### 4\.5 页面UI与适配需求

- **整体风格**：极简、清新、轻量化学生风格，配色统一、无花哨样式，专注学习氛围。

- **布局规范**：采用Flex弹性布局，页面结构分层清晰，头部功能区、核心计时区、任务打卡区、底部统计区层级明确。

- **响应式适配**：兼容电脑端、平板、手机端，不同设备页面自动适配，无横向滚动、元素挤压、留白错乱问题。

- **交互体验**：按钮、卡片添加hover过渡动画，点击反馈清晰，操作流畅无卡顿。

## 5\. 数据与接口规范（Mock API \+ 本地缓存双方案）

本项目采用**工程化双层数据方案**，优先通过Mock API请求模拟后端数据，实现标准前后端交互逻辑；网络异常/离线场景自动降级为LocalStorage本地存储兜底。同时统一接口数据结构与本地缓存结构，保证数据一致性，适配AI Coding批量生成接口请求、联调、容错代码。

### 5\.1 整体接口设计规范

- **接口基础地址**：/api

- **请求方式**：遵循RESTful规范（GET查询、POST新增、PUT修改、DELETE删除）

- **统一返回格式**：所有接口返回标准化JSON结构，方便全局拦截处理

```json
{
  "code": 200, // 状态码：200成功、500失败
  "msg": "操作提示信息",
  "data": {} // 核心业务数据
}
```

### 5\.2 全部Mock API接口清单

#### 5\.2\.1 计时器配置接口

- 获取默认计时配置：**GET /api/timer/config**

- 保存自定义计时配置：**PUT /api/timer/config**

#### 5\.2\.2 学习任务接口

- 获取任务列表：**GET /api/task/list**

- 新增学习任务：**POST /api/task/add**

- 更新任务状态/内容：**PUT /api/task/update**

- 删除单条任务：**DELETE /api/task/delete**

#### 5\.2\.3 学习打卡接口

- 获取全部打卡记录：**GET /api/clock/list**

- 提交当日学习打卡：**POST /api/clock/add**

#### 5\.2\.4 数据统计接口

- 获取近7天学习统计数据：**GET /api/stat/week**

- 获取近30天学习统计数据：**GET /api/stat/month**

### 5\.3 接口对应数据结构

### 5\.1 任务列表数据结构

```json
// 任务列表数据结构（Mock接口返回/本地缓存通用）
[
  {
    "id": "唯一时间戳ID",
    "content": "任务内容",
    "status": "0/1", // 0：未完成  1：已完成
    "createTime": "创建时间"
  }
]
```

### 5\.2 打卡记录数据结构

```json
// 打卡记录数据结构（Mock接口返回/本地缓存通用）
[
  {
    "date": "YYYY-MM-DD", // 打卡日期（唯一）
    "studyTime": "当日累计专注时长(分钟)",
    "createTime": "打卡具体时间"
  }
]
```

### 5\.3 计时器配置数据结构

```json
// 计时器配置数据结构（Mock接口返回/本地缓存通用）
{
  "studyDuration": 25, // 默认学习时长
  "restDuration": 5 // 默认休息时长
}
```

### 5\.4 双层数据联动逻辑

Apifox 用于模拟标准 RESTful 交互，LocalStorage 负责浏览器侧持久化。

- **优先接口请求**：页面初始化、功能操作后，优先发起Mock API请求获取/提交数据；

- **离线自动兜底**：接口请求失败、无网络、Mock服务异常时，自动读取/写入LocalStorage，保证功能可用；

- **双向数据同步**：接口请求成功后自动同步最新数据到本地缓存，兜底操作后，网络恢复可自动同步至Mock服务；

- **加载状态处理**：所有接口请求过程中展示loading状态，请求结束后关闭loading，提升交互体验。

## 6\. 非功能性需求

### 6\.1 性能需求

- 页面首次加载速度快，无冗余资源加载；

- 计时运行流畅，无卡顿、时间漂移问题；

- 接口请求高效稳定，异步数据渲染无卡顿、无数据错乱问题。

### 6\.2 稳定性需求

- 完善的异常容错机制，杜绝非法输入导致功能报错；

- 定时器无叠加、无内存泄漏，长期运行稳定；

- 接口请求完善异常处理（超时、失败、重复请求拦截），本地存储兜底读写安全，无数据丢失、错乱问题。

### 6\.3 可拓展性需求

- 代码模块化、组件化拆分清晰，支持后续拓展云端存储、用户登录、数据导出、学习周报生成等功能；

- 数据结构设计通用，支持后续新增统计维度、任务分类等需求。

### 6\.4 可维护性需求

- 代码命名规范、注释完整，层级清晰；

- 功能单一职责，模块解耦，便于调试、修改、重构；

- 适配AI辅助接口开发、联调、报错排查，兼容主流AI编码工具生成请求、Mock数据、容错代码逻辑。
